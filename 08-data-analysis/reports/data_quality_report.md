## 3. Missing-value strategy, per column (with justification)

| column | strategy | justification |
| --- | --- | --- |
| orders.quantity | drop row | Quantity is a core measure: without it no revenue can be computed and imputing it would invent turnover. Missingness is ~0.5% and shows no pattern by channel/region (MCAR), so dropping is safe. |
| orders.discount | fill 0.0 | In the source system a blank discount field means 'no promotion code applied'. ~58% of populated rows are already 0.0, so 0 is both the modal and the semantically correct value. |
| orders.shipping_cost | median by channel x region | Shipping is essentially a lookup on channel (Retail Store = 0) and delivery region. The group median is robust to the long right tail of the shipping distribution; a global mean would over-charge cheap-to-serve regions. |
| orders.payment_method | fill 'Unknown' | Un-imputable categorical. Filling with the mode would inflate 'Credit Card' share and bias any payment-mix reporting; an explicit 'Unknown' level keeps the bias visible. |
| orders.region | back-fill from customers.region, else 'Unknown' | customers.csv is the authoritative source for a customer's region, so the value can be recovered exactly rather than guessed. |
| customers.age | median by segment (+ is_age_imputed flag) | Age is skewed and used for profiling only. Segment medians preserve the between-segment differences; the flag lets any analysis exclude imputed rows. Impossible ages (<16, >100) are nulled first. |
| customers.gender | fill 'Unknown' | Sensitive attribute - imputing it would fabricate demographics. An explicit 'Unknown' level is the honest representation. |
| customers.city | fill 'Unknown' | Free-text field with no reliable donor column at row level; region is retained separately so no geographic analysis is lost. |
| products.supplier | fill 'Unknown' | Supplier is a reporting dimension only; a placeholder keeps the product row (and its revenue) in the analysis. |
| products.subcategory | fill 'Unspecified' | Same as supplier - dropping the product would silently remove its sales from every category roll-up. |

## 5. Outlier handling

Outliers are detected with the Tukey/IQR fence and **flagged, not deleted**:

* `is_price_outlier` - 5,422 lines (11.04%) outside `Q1-1.5*IQR .. Q3+1.5*IQR` on `unit_price`.
* `is_revenue_outlier` - 3,188 lines (6.49%) outside the k=3 fence on line revenue.
* `is_return` - 392 lines (0.80%) with a negative quantity; these are genuine credit notes and are kept so that *net* revenue is reported.

Keeping the rows means headline revenue stays reconciled with the source ledger, while any analysis can exclude them with a single boolean filter.
