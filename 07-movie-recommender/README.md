# 🎬 Movie Recommender

A complete, offline, dependency-light movie recommendation system: content-based
filtering, item-item collaborative filtering, SVD matrix factorisation, a tunable
hybrid of the three, an evaluation harness, a CLI and a Streamlit UI.

Everything runs from data committed to this repository — **no network access is
needed at runtime**.

```
python cli.py recommend --title "The Matrix" --n 5
python cli.py recommend --user 42 --method hybrid --alpha 0.4 --why
streamlit run app.py
```

---

## Dataset

### `data/movies.csv` — 346 movies

Hand-written catalogue of well-known films. Columns:

| column | description |
|---|---|
| `movie_id` | 1..346, primary key |
| `title`, `year` | film title and release year |
| `genres` | `\|`-separated, 19 distinct genres (Action, Drama, Sci-Fi, …) |
| `director` | single director |
| `cast` | `\|`-separated, top five billed actors |
| `keywords` | `\|`-separated, 6 plot/theme tags |
| `overview` | one-line synopsis, written for this project (not copied from any database) |
| `runtime`, `language` | minutes, ISO-639-1 language code |
| `vote_average`, `vote_count` | approximate public rating and vote volume, used only for the popularity prior |

Titles, years, genres, directors and cast are public factual metadata; the
`overview` text is original.

### `data/ratings.csv` — 20,019 **synthetic** ratings

> ⚠️ **The ratings are not real user data.** They are generated by
> `data/generate_ratings.py` from a fixed seed (`SEED = 42`). Re-running the
> script reproduces the committed file byte-for-byte.

| property | value |
|---|---|
| users | 600 |
| movies rated | 346 (full catalogue) |
| ratings | 20,019 (0.5 – 5.0 in half-star steps) |
| density | 9.64 % |
| mean / std | 3.52 / 1.20 |

The generator is deliberately *not* random noise — it builds a latent factor
model so that collaborative filtering has something real to recover:

1. Each user is a blend of two of eight **taste archetypes** (blockbuster,
   cinephile, horror, romantic, family/animation, crime-thriller, sci-fi,
   comedy) plus Gaussian jitter → a preference vector `p_u` over the 19 genres.
2. Each movie has a genre vector `q_i` (L2-normalised over its genres), an
   acclaim factor and a release-year factor.
3. Affinity `a_ui = <p_u, q_i> + quality-sensitivity + era-preference`, standardised.
4. **Who rates what** is biased: exposure `= 0.95·fame + 0.55·a_ui + noise`, and
   each user's films are drawn from the softmax of that via the Gumbel-top-k
   trick. This reproduces the *non-uniformly missing* structure of real rating data.
5. The rating itself:

   ```
   r_ui = μ + b_u + b_i + w·a_ui + ε ,  ε ~ N(0, 0.42²)
   r_ui = clip(round(r_ui · 2) / 2, 0.5, 5.0)
   ```

   with `μ = 2.90`, `w = 1.15`, `b_u ~ N(0, 0.38²)` and `b_i` driven by acclaim.

Regenerate with:

```bash
python data/generate_ratings.py            # writes data/ratings.csv
python data/generate_ratings.py --users 1000 --ratings 50000 --seed 7
```

## Algorithms

### 1. Content-based filtering — `src/content_based.py`

Every movie is flattened into a "soup" of tokens, with fields repeated to weight
them (genres ×5, director ×4, keywords ×3, top-4 cast ×3, overview ×1). Multi-word
names collapse into single tokens (`Christopher Nolan → christophernolan`) so the
model matches people, not first names.

The soup is vectorised with TF-IDF (sublinear term frequency, English stop words):

```
tf-idf(t, d) = (1 + log tf(t,d)) · log((1 + n) / (1 + df(t))) + 1     (L2-normalised rows)
```

and movies are compared with cosine similarity:

```
sim(i, j) = (v_i · v_j) / (||v_i|| ||v_j||)
```

`recommend(title, n)` resolves the title through **exact → substring → difflib
fuzzy** matching (so `"incepton"` and `"godfather"` both work), zeroes the
self-similarity and returns the top *n*. Unmatched titles raise
`TitleNotFoundError` carrying "did you mean" suggestions (difflib, falling back
to token overlap).

### 2. Collaborative filtering — `src/collaborative.py`

Both models operate on a sparse `600 × 346` `scipy.sparse.csr_matrix`.

**Item-item CF (adjusted cosine).** Ratings are mean-centred *per user* on the
observed entries only, so a generous rater and a harsh rater become comparable:

```
sim(i, j) = Σ_u (r_ui - r̄_u)(r_uj - r̄_u) / sqrt(Σ_u (r_ui - r̄_u)² · Σ_u (r_uj - r̄_u)²)
```

Similarities are shrunk by co-rating support, `sim' = sim · c_ij / (c_ij + λ)`
with `λ = 5`, which kills spurious 1.0 similarities from two-user overlaps.
Prediction uses the *k = 15* nearest rated neighbours:

```
r̂_ui = r̄_u + Σ_{j ∈ N_k(i)} sim'(i,j)(r_uj - r̄_u) / Σ_{j ∈ N_k(i)} |sim'(i,j)|
```

**SVD matrix factorisation.** Baselines are removed first
(`b_ui = μ + b_u + b_i`), then `TruncatedSVD` factorises the residual matrix into
`k = 8` latent factors:

```
R - B ≈ U Σ Vᵀ         r̂_ui = μ + b_u + b_i + (UΣ)_u · V_i
```

Predictions are clipped to `[0.5, 5]`. Unknown users fall back to item means,
unknown movies to user means, and unknown both to the global mean.

### 3. Hybrid — `src/hybrid.py`

Content and collaborative scores are min-max normalised onto `[0, 1]` and blended:

```
score(i) = α · content(i) + (1 - α) · collaborative(i) + 0.05 · popularity(i)
```

`α = 1` is pure content, `α = 0` is pure collaborative. The content term is the
similarity to a seed title, or the rating-weighted similarity to everything the
user liked (≥ 4★). The collaborative term is the SVD (or item-item) score for a
known user, or item-item similarity to the seed title.

**Cold start.** Users with fewer than 3 ratings (or no user at all and no seed
title) get the IMDb weighted rating instead:

```
WR = v/(v + m) · R + m/(v + m) · C
```

where `R` = the movie's mean rating, `v` = its number of votes, `m` = the 70th
percentile of vote counts and `C` = the mean rating over the whole catalogue.
This pulls thinly-rated films toward the global mean instead of letting a single
5★ vote top the chart.

### 4. Evaluation — `src/evaluate.py`

Per-user 20 % random hold-out (seed 42, every user keeps ≥ 5 training ratings).
Rating predictors are scored with RMSE and MAE; rankers produce a top-10 out of
all unseen movies and are scored with Precision@K, Recall@K, MAP@K and catalogue
coverage. An item is *relevant* if the held-out rating is ≥ 4.0.

```
RMSE = sqrt( (1/N) Σ (r - r̂)² )                 MAE = (1/N) Σ |r - r̂|
P@K  = |top-K ∩ relevant| / K                    R@K = |top-K ∩ relevant| / |relevant|
AP@K = (1/min(|relevant|,K)) Σ_{k: hit} P@k      MAP@K = mean over users of AP@K
Coverage = |distinct movies recommended to anyone| / |catalogue|
```

```
SVD                    |       0.0625 |    0.1846 | 0.0644 |   0.1474 |   558
Hybrid (alpha=0.5)     |       0.0724 |    0.2061 | 0.0823 |   0.4971 |   558
Hybrid (alpha=0.25)    |       0.0815 |    0.2329 | 0.0964 |   0.3382 |   558
```

How to read it:

* Both collaborative models beat the bias-only baseline on RMSE — item-item CF by
  **7.5 %** (0.897 → 0.830), SVD by 6.4 %. The residual error is close to the
  0.42★ noise floor baked into the generator, so there is not much left to win.
* Popularity is a *strong* ranking baseline here (as it is in real life) because
  exposure in the generator is correlated with fame — but it recommends the same
  ~22 films to everybody (coverage 6 %).
* The hybrid at `α = 0.25` is the only model that beats popularity on MAP@10
  (0.0964 vs 0.0905) while recommending **5× more of the catalogue** (34 % vs 6 %).
* Content-based filtering has the best coverage (76 %) and needs no ratings at
  all — which is exactly why it carries the cold-start and seed-title cases.

## Usage

### CLI

```bash
# content-based: movies like this one
python cli.py recommend --title "The Matrix" --n 5 --method content

# personalised collaborative filtering
python cli.py recommend --user 42 --n 10 --method cf
python cli.py recommend --user 42 --n 10 --method svd

# hybrid, with explanations, tuned toward collaborative
python cli.py recommend --user 42 --n 10 --method hybrid --alpha 0.3 --why

# hybrid seeded on a title *and* a user
python cli.py recommend --user 42 --title "Alien" --alpha 0.6

# other commands
python cli.py predict  --user 42 --title "The Matrix"
python cli.py search   "star"
python cli.py info
python cli.py evaluate --k 10
```

### Streamlit

```bash
streamlit run app.py
# or headless:
streamlit run app.py --server.headless true --server.port 8507
```

The UI lets you pick a seed movie (dropdown or fuzzy free text), personalise for
a user id, switch between hybrid / content / item-item CF / SVD / popularity,
and drag the **α** slider between content and collaborative. Results render as
cards with genre badges, year, director, runtime, score bar and a **"why this?"**
line listing the shared genres, director, cast and keywords (or the user's own
rating that triggered the recommendation).

## Limitations

* **The ratings are synthetic.** Every number in the evaluation table describes
  how well each model recovers the structure `data/generate_ratings.py` put
  there. Absolute values will differ on MovieLens or real traffic; the relative
  ordering of the models is the informative part.
* **Small catalogue (346 films).** Coverage and precision figures are optimistic
  compared to a 10,000-title catalogue, and the item-item similarity matrix is
  dense in memory (`O(n²)` floats) — fine at this size, not at 100k movies.
* **TruncatedSVD treats missing ratings as zero residuals**, which biases factors
  toward the baseline. A proper SGD/ALS factorisation over observed entries only
  (Funk SVD, implicit-ALS, BPR) would do better; the low optimum of `k = 8` is a
  symptom of this plus the small number of ratings per user (~27 in training).
* **No time awareness.** The generated timestamps are ignored; the split is
  random per user rather than chronological, which leaks a little future
  information compared to a production setting.
* **Popularity bias.** Exposure in the generator (like real catalogues) favours
  famous films, so a popularity baseline is hard to beat on precision. The hybrid
  compensates with coverage, but the metrics cannot see novelty or serendipity.
* **Cold-start movies** get no personalisation at all — a brand new title with no
  ratings is reachable only through the content model or the popularity prior.
* **Explanations are post-hoc.** The "why this?" text is computed from shared
  metadata, not from the factor that actually drove the collaborative score.
